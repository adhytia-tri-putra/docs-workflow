Panduan Tim

Git workflow yang sederhana dan konsisten.

Panduan praktis untuk membuat branch, menyimpan perubahan, dan mengirim pull request tanpa membuat riwayat repository berantakan.

Lihat alur kerja

Persiapan awal

Atur identitas Git satu kali sebelum mulai bekerja.

git config --global user.name "Nama Kamu"
git config --global user.email "email@example.com"

Clone repository dan masuk ke direktori project.

git clone https://github.com/organisasi/project.git
cd project

Strategi branch

main

Production

Berisi kode stabil dan siap dirilis. Hindari commit langsung ke branch ini.

feature/*

Fitur baru

Gunakan untuk pengembangan fitur, misalnya feature/login.

fix/*

Perbaikan

Gunakan untuk perbaikan bug, misalnya fix/navbar-mobile.

Alur kerja harian

  1. Perbarui branch utamaPastikan pekerjaan dimulai dari versi terbaru.
    git switch main
git pull origin main
  2. Buat branch pekerjaanPilih nama singkat yang menjelaskan tujuan perubahan.
    git switch -c feature/nama-fitur
  3. Simpan perubahanPeriksa file sebelum membuat commit.
    git status
git add .
git commit -m "feat: tambah nama fitur"
  4. Kirim branchPush branch lalu buat pull request di GitHub atau GitLab.
    git push -u origin feature/nama-fitur

Aturan commit

Gunakan format tipe: deskripsi singkat agar riwayat mudah dibaca.

feat: fitur baru

fix: perbaikan bug

docs: perubahan dokumentasi

refactor: perubahan kode tanpa mengubah perilaku

test: penambahan atau perbaikan test

chore: tugas pemeliharaan

Contoh: fix: perbaiki validasi email saat login

Pull request

  • Judul menjelaskan perubahan dengan singkat.
  • Deskripsi memuat alasan dan dampak perubahan.
  • Test sudah dijalankan dan berhasil.
  • Perubahan sudah ditinjau sendiri sebelum meminta review.
  • Gabungkan setelah mendapat persetujuan reviewer.

Mengatasi konflik

Perbarui branch pekerjaan, selesaikan penanda konflik di editor, lalu commit hasilnya.

git switch feature/nama-fitur
git fetch origin
git merge origin/main
# perbaiki file yang konflik
git adds .
git commit -m "chore: selesaikan merge conflict"
Penting: Jangan menghapus perubahan rekan satu tim tanpa memahami konteksnya.
